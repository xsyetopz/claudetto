# The Secret Redaction of the Handoff

A handoff file crosses a context boundary as a file on disk, so the writer masks every secret before it writes (spec `session-handoff`, requirement "Handoff Points, Does Not Copy", task 4.8). None of the three prior-art repositories redacts anything (`handoff-prior-art.md`, "Redaction"), so no pattern here is this project's invention: they come from two rule sets that already exist, in two passes over the text.

| --- | --- | --- | --- |
| The table | Claude Code `2.1.312`, module `chunk-45pm9m17.js` | 65 | Transcribed, read offset by offset |
| The Gitleaks rules | `gitleaks/gitleaks` `v8.30.1`, `config/gitleaks.toml` | 216 | Fetched and generated by `just gitleaks-rules` |

## What the Rebuild Runs

`plugins/claudetto/src/secrets/redact.ts` is the program's own redaction order: the private key blocks of `Xls`, then the 13 `low` rows, then the 52 `high` ones, each row gated by its prefilter as `lt` gates it, and each hit replaced by `Fe`. The rows are compiled by `be(true)`, which is the compiler the program's own redaction calls, so a row with a capture group keeps the boundary the pattern needed and loses only the group.

All 65 rows ship, which `tests/claudetto/redact.test.ts` asserts by id. This closes the gap the archived file recorded as "a floor, not the whole table": the eleven GitLab tokens were missing there because that file compiled the `high` rows the way `Yi()` does, and `Yi()` is the display path, which `redactForDisplay` alone calls.

## The Two Deviations

Both come from one fact: a handoff is Markdown, and a backtick must survive.

1. `RUN`, the program's `Cn`, takes the backtick into the characters that end an unquoted value. Without it the closing backtick of `` `KEY=secret` `` is read as part of the value and masked, and the file loses its code span. The boundary group `pt` of the same table already names the backtick as a character that ends a secret value, so the character is the program's choice and only the place is ours.
2. The masked alternative of `VALUE`, the program's `Ge`, drops the trailing `['"\x60]?`. `Fe` puts a quote back only when the value both opens and closes with one, so a second pass over `` `KEY=[REDACTED]` `` would swallow the closing backtick.

Case `a second pass over a redacted code span keeps the span closed` holds the second one.

## What Is Left Out

- The tracked-URL path, `Me`, `Ln`, `Ki`, `trackedContext`, and `fe`, which keeps the shape of a URL while it masks the credential inside it. Without it a URL is masked by the plain rows alone, which takes more of the line and never less. A handoff may carry a shorter URL; it may not carry a secret.
- The scan path and the finding labels, `be(false)`, `scan`, `Os`, and `Ta`, because nothing in a handoff reports a finding.
- The display path, `Yi` and `redactForDisplay`, and with it the field `displayRun`, which no redaction row reads.
- The index pre-scan `jn`, which only finds the first `-----BEGIN` faster than `gt` does.
- The name predicate `fwe` of `chunk-7gjh0jc7.js` at offset 43,635, which the archived note also left out.

The values of the credential environment variables of the session are not covered, and no mod can cover them: `$.env.get` refuses a name that is not a literal at the call site. A leak of such a value through the session text is caught only where the text also holds the name, which the rows `sensitive-assign` and `cloud-env-var` read.

## The Gitleaks Rules

The table of the program names 65 shapes. The default config of Gitleaks names 222 rules, each with the keyword gate, the entropy bound, and the allowlists its author tuned, so the second pass adds the vendors the table does not name and this tree writes no pattern of its own.

Nothing of it is copied by hand. `just gitleaks-rules --fetch` downloads `config/gitleaks.toml` and `LICENSE` at the pinned ref, writes both under `docs/keep/gitleaks/`, and generates `plugins/claudetto/src/secrets/gitleaks/rules.ts`. Updating to a newer release is `just gitleaks-rules --fetch --ref TAG` and one edit of `REF` in `tools/gitleaks/run.ts`.

The data ships as one JSON string and not as TypeScript rows for two reasons, both measured and not assumed: the mod loader of Claude Code refuses a `.json` import, which a probe proved by its refusal, and 216 formatted rules are some 3,000 lines against the `MAX_SOURCE_LINES` cap of 300.

### Two Digests, Two Checks

| Check | Runs | Compares |
| --- | --- | --- |
| `bun tools/gitleaks/run.ts --check`, inside `just validate` | Offline, in the gate | The generated module against a regeneration from the vendored config, byte for byte |
| `just gitleaks-rules --upstream` | On demand, over the network | The digest of the vendored config against the original at the pinned ref, and against the newest release |

The config at `v8.30.1` has the SHA-256 `e163e53b9e7e8a8511e77271e2b323ed057759542a6d988258afe3a1fa329caf`, which the generated module records and `tests/claudetto/gitleaks.test.ts` recomputes from the vendored file. An edit to either side fails the gate, so a hand-tuned rule cannot ride along unnoticed.

### What the Translation Changes

Gitleaks writes for Go's `regexp`, so 134 of the 222 patterns carry an inline flag setter, `(?i)`, which JavaScript throws on. A setter at the head of a pattern becomes the `i` flag; a setter inside becomes a modifier group `(?i:...)` that runs to the end of the group enclosing it, which is the scope Go gives it. A modifier group the config already writes, in 16 patterns, is left as it stands. The config uses no lookaround, which is the construct where RE2 and JavaScript really part, so nothing else needed a change: `tools/gitleaks/translate.ts` compiles every result and the generator drops what will not compile.

### What Is Left Out, and Why

Seven of the 222 rules do not ship, and `gitleaksDropped()` lists each with its reason.

- `freemius-secret-key`, `hashicorp-tf-password`, `kubernetes-secret-yaml`, and `nuget-config-password` fire only on a file whose name matches, such as `nuget.config`. A handoff reads a transcript, where no file name exists, so the rule can never fire.
- `pkcs12-file` carries no pattern at all, only a file name.
- `jwt-base64` writes its 34 capture groups in Go's spelling, `(?P<alg>...)`, which JavaScript spells `(?<alg>...)`. Its groups mark which header a token carries rather than the token, so the rule is left out rather than translated into a mask that would replace a ten-character fragment of a key.
- One allowlist of `generic-api-key`, the one of `condition = "AND"` over the BitBake paths, needs a file path for every criterion and so can never be satisfied.

The `paths` criterion of an allowlist goes for the same reason, and `commits` belongs to a Git scan. The `gitleaks:allow` line signature, which turns a finding off from inside the text, is deliberately not taken: a transcript holds text that a model and a web page wrote, and a line carrying the signature would turn redaction off from the data.

### Where the Semantics Were Read

From the Gitleaks source at the pinned ref, not from its documentation: `detect/detect.go` for the secret of a hit (line 521), the entropy bound (547), and the order of the global allowlists before a rule's own (557); `config/allowlist.go` for `RegexAllowed`, `ContainsStopWord`, and the `AND` condition. Two details would have been wrong from memory. The secret of a hit is the first capture group that is not empty, not group one; and an allowlist's stopwords always read that secret while only its `regexes` follow `regexTarget`.

One deviation from Gitleaks is deliberate. `microsoft-teams-webhook` captures `([a-z0-9]{4}-){3}`, one chunk of a UUID inside a whole webhook URL, and Gitleaks reports that chunk as the secret. Reporting a fragment costs a scanner nothing; masking a fragment would leave the URL working, which a run showed with five characters replaced and the webhook intact. A rule whose capture group repeats is therefore masked whole, which `tools/gitleaks/build.ts` decides at generation. It is the only such rule of the 216, and no row of the program's table has the shape.

## What It Costs

The writer runs inside the bound of `session.end`, which keeps a reserve of 400 ms for the write itself (`WRITE_RESERVE_MS` of `plugins/claudetto/src/register.ts`). Measured on 2026-10-29 against two of this login's own transcripts, each read as the writer reads one, `tail -c 262144`:

| Transcript | Turns with text | Characters | The table alone | `parseTail` whole |
| --- | --- | --- | --- | --- |
| `5007385e` of this project | 1 | 3,295 | 0.1 ms | 6.6 ms |
| `64a01683` of `claude-code-docs` | 15 | 7,734 | 0.4 ms | 6.6 ms |

A tail of 262,144 characters yields few turns with text, because tool results take most of the bytes.

The second pass was priced the same day over a wider sample: the 40 largest transcripts of this login, 1,070 turn texts and 856,525 characters in all, each text redacted as `parseTail` redacts it. The table takes 0.039 ms for one text and both passes take 0.063 ms, so the Gitleaks rules cost 0.024 ms a text, or some 0.3 ms for the twelve turns of a handoff. One pass over the whole 262,144-character tail, which is the worst case the writer could ever hand it, takes 15 ms to 17 ms.

The same sample measures the false positives, which is the real risk of 216 more patterns: across those 1,070 turn texts the Gitleaks rules added no mask at all, and the table added none either. Over the raw transcript bytes, which hold the request metadata that `parseTail` never reads, the rules mask 16 to 19 spans per tail, nearly all of them `generic-api-key` reading a beta header name after the word `oauth`. Both readings were taken with a one-off script that was deleted after it ran, because no recipe needs it.

## Where It Is Applied

In `parseTail` of `plugins/claudetto/src/handoff.ts`, at the read, on each turn's text and on each touched path, so no secret of the session is carried further in than the reader. The field `written` is the one exception: it never reaches the file, and `wroteOwn` matches the handoff folder inside it, which a redaction of the path could break.
