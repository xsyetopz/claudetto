# The Secret Redaction of the Handoff

A handoff file crosses a context boundary as a file on disk, so the writer masks every secret before it writes (spec `session-handoff`, requirement "Handoff Points, Does Not Copy", task 4.8). None of the three prior-art repositories redacts anything (`handoff-prior-art.md`, "Redaction"), so no pattern here is this project's invention: they come from two rule sets that already exist, in two passes over the text.

| The Gitleaks rules | `gitleaks/gitleaks` `v8.30.1`, `config/gitleaks.toml` | 216 of its 222 | Fetched and generated by `just gitleaks-rules` |

## What the Rebuild Runs

`plugins/claudetto/src/shared/secrets/redact.ts` is the program's own redaction order: the private key blocks of `Xls`, then the 13 `low` rows, then the 52 `high` ones, each row gated by its prefilter as `lt` gates it, and each hit replaced by `Fe`. The rows are compiled by `be(true)`, which is the compiler the program's own redaction calls, so a row with a capture group keeps the boundary the pattern needed and loses only the group.

All 65 rows ship, which `tests/claudetto/redact.test.ts` asserts by id. This closes the gap the archived file recorded as "a floor, not the whole table": the eleven GitLab tokens were missing there because that file compiled the `high` rows the way `Yi()` does, and `Yi()` is the display path, which `redactForDisplay` alone calls.

## The Two Deviations

Both come from one fact: a handoff is Markdown, and a backtick must survive.

1. `RUN`, the program's `Cn`, takes the backtick into the characters that end an unquoted value. Without it the closing backtick of `` `KEY=secret` `` is read as part of the value and masked, and the file loses its code span. The boundary group `pt` of the same table already names the backtick as a character that ends a secret value, so the character is the program's choice and only the place is ours.
2. The masked alternative of `VALUE`, the program's `Ge`, drops the trailing `['"\x60]?`. `Fe` puts a quote back only when the value both opens and closes with one, so a second pass over `` `KEY=[REDACTED]` `` would swallow the closing backtick.

Case `a second pass over a redacted code span keeps the span closed` holds the second one.

## What Is Left Out

- The tracked-URL path, `Me`, `Ln`, `Ki`, `trackedContext`, and `fe`, which keeps the shape of a URL while it masks the credential inside it. Without it a URL is masked by the plain rows alone, which takes more of the line and never less. A handoff may carry a shorter URL; it may not carry a secret.
- The scan path and the finding labels, `be(false)`, `scan`, `Os`, and `Ta`, because nothing in a handoff reports a finding.
- The display path, `Yi` and `redactForDisplay`, and with it the field `displayRun`, which no redaction row reads.
- The index pre-scan `jn`, which only finds the first `-----BEGIN` faster than `gt` does.
- The name predicate `fwe` of `chunk-7gjh0jc7.js` at offset 43,635, which the archived note also left out.

The values of the credential environment variables of the session are not covered, and no mod can cover them: `$.env.get` refuses a name that is not a literal at the call site. A leak of such a value through the session text is caught only where the text also holds the name, which the rows `sensitive-assign` and `cloud-env-var` read.

## The Gitleaks Rules

The table of the program names 65 shapes. The default config of Gitleaks at `v8.30.1` names 222 rules, each with the keyword gate, the entropy bound, and the allowlists its author tuned, so the second pass adds the vendors the table does not name and this tree writes no pattern of its own.

Nothing of it is copied by hand. `just gitleaks-rules --fetch` downloads `config/gitleaks.toml` and `LICENSE` at the pinned ref, writes both under `docs/keep/gitleaks/`, and generates `plugins/claudetto/src/shared/secrets/gitleaks/rules.ts`. Updating to a newer release is `just gitleaks-rules --fetch --ref TAG` and one edit of `REF` in `tools/gitleaks/run.ts`.

The data ships as one JSON string and not as TypeScript rows for two reasons. The mod loader of Claude Code refuses a `.json` import, which a probe showed by its refusal and which was not rerun on 2026-11-03. And the 216 rules as JSON indented by two spaces are 4,286 lines (`JSON.stringify(data, null, 2)`, counted on 2026-11-03) against the `MAX_SOURCE_LINES` cap of 300 in `tools/limits.ts`.

### Two Digests, Two Checks

| Check | Runs | Compares |
| --- | --- | --- |
| `bun tools/gitleaks/run.ts --check`, inside `just validate` | Offline, in the gate | The generated module against a regeneration from the vendored config, byte for byte |
| `just gitleaks-rules --upstream` | On demand, over the network | The digest of the vendored config against the original at the pinned ref, and against the newest release |

The config at `v8.30.1` has the SHA-256 `e163e53b9e7e8a8511e77271e2b323ed057759542a6d988258afe3a1fa329caf`, which the generated module records and `tests/claudetto/gitleaks.test.ts` recomputes from the vendored file. An edit to either side fails the gate, so a hand-tuned rule cannot ride along unnoticed.

### What the Translation Changes

Gitleaks writes for Go's `regexp`, so 134 of the 222 patterns carry an inline flag setter, `(?i)` (counted on 2026-11-03 over the `regex` lines of `docs/keep/gitleaks/gitleaks.toml`), which JavaScript throws on. A setter at the head of a pattern becomes the `i` flag; a setter inside becomes a modifier group `(?i:...)` that runs to the end of the group enclosing it, which is the scope Go gives it. A modifier group the config already writes, in 16 patterns, is left as it stands. The config uses no lookaround, which is the construct where RE2 and JavaScript really part, so nothing else needed a change: `tools/gitleaks/translate.ts` compiles every result and the generator drops what will not compile.

### What Is Left Out, and Why

Six of the 222 rules do not ship and one allowlist is not applied. `gitleaksDropped()` lists the seven entries with their reasons, and `bun` over it printed `freemius-secret-key`, `generic-api-key`, `hashicorp-tf-password`, `jwt-base64`, `kubernetes-secret-yaml`, `nuget-config-password`, and `pkcs12-file` on 2026-11-03.

- `freemius-secret-key`, `hashicorp-tf-password`, `kubernetes-secret-yaml`, and `nuget-config-password` fire only on a file whose name matches, such as `nuget.config`. A handoff reads a transcript, where no file name exists, so the rule can never fire.
- `pkcs12-file` carries no pattern at all, only a file name.
- `jwt-base64` writes its 34 capture groups in Go's spelling, `(?P<alg>...)`, which JavaScript spells `(?<alg>...)`. Its groups mark which header a token carries rather than the token, so the rule is left out rather than translated into a mask that would replace a ten-character fragment of a key.
- One allowlist of `generic-api-key`, the one of `condition = "AND"` over the BitBake paths, needs a file path for every criterion and so can never be satisfied.

The `paths` criterion of an allowlist goes for the same reason, and `commits` belongs to a Git scan. The `gitleaks:allow` line signature, which turns a finding off from inside the text, is deliberately not taken: a transcript holds text that a model and a web page wrote, and a line carrying the signature would turn redaction off from the data.

### Where the Semantics Were Read

From the Gitleaks source at the pinned ref, not from its documentation. The lines were fetched again on 2026-11-03 from `raw.githubusercontent.com/gitleaks/gitleaks/v8.30.1/detect/detect.go`: the secret of a hit (line 521), the entropy bound (547), and the global allowlists (557). The ordering of the global allowlists before a rule's own is not rechecked. `config/allowlist.go` holds `RegexAllowed` and `ContainsStopWord`, and `checkFindingAllowed` (`detect.go:823`) holds the `AND` condition. Two details would have been wrong from memory. The secret of a hit is the first capture group that is not empty when `secretGroup` is unset (`detect.go:533-538`), not group one; and an allowlist's stopwords always read that secret (`detect.go:846`) while only its `regexes` follow `regexTarget` (`detect.go:831-845`).

One deviation from Gitleaks is deliberate. `microsoft-teams-webhook` captures `([a-z0-9]{4}-){3}`, one chunk of a UUID inside a whole webhook URL, and Gitleaks reports that chunk as the secret. Reporting a fragment costs a scanner nothing; masking a fragment would leave the URL working, a claim that no run in this tree backs, so it is unmeasured. A rule whose capture group repeats is therefore masked whole, which `tools/gitleaks/build.ts` decides at generation. A read of the shipped data on 2026-11-03 finds the field `whole` on `microsoft-teams-webhook` alone. Whether a row of the program's table has the shape was not checked.

## What It Costs

The writer runs inside the bound of `session.end`, which keeps a reserve of 400 ms for the write itself (`WRITE_RESERVE_MS` at `plugins/claudetto/src/blocks/handoff/block.ts:28`). It reads the last 262,144 bytes of the transcript (`TAIL_BYTES` at `plugins/claudetto/src/blocks/handoff/handoff.ts:6`) and keeps 12 turns (`TURNS` at `:8`).

The time that the table and the Gitleaks rules cost per text, and the number of false positives over real transcripts, were measured on 2026-10-29 by a one-off script that was deleted after it ran. The numbers cannot be reproduced, so this page states none. They are unmeasured.

## Where It Is Applied

In `parseTail` of `plugins/claudetto/src/blocks/handoff/handoff.ts`, at the read, on each turn's text and on each touched path, so no secret of the session is carried further in than the reader. The field `written` is the one exception: it never reaches the file, and `wroteOwn` matches the handoff folder inside it, which a redaction of the path could break.
