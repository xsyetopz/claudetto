QUESTION: Can built-in commands also be disabled at will? How many exist? List them, if they can be disabled. Asked by the user on 2026-10-27.
VERSION: Claude Code `2.1.311`, read with `cc-inspect` `surface` kind `slash-command` and `kind` `env`, and against the published source of the four built-in mods at `anthropics/claude-code` `mods/`.
SHORT ANSWER: No, not at will, and not by one switch. `2.1.311` has `142` built-in slash commands. `37` are type `prompt`, which are the bundled skills, and a settings key turns each of those off by name. The other `105` are type `local` or `local-jsx`, which no settings key reaches: `10` of them have their own environment variable, `4` are already off in this build, `10` are hidden, and the rest can only be stopped by a mod that hooks `command.run`.

MECHANISM 1, PER-SKILL, REACHES THE 37 `prompt` COMMANDS: `skillOverrides`, keyed by skill name. The settings schema of `2.1.311` (`chunk-z1xn9dp7.js:145792`) gives `off`, which "hides it from both" the model and `/name`, and `user-invocable-only`, which "hides it from the model but keeps /name". So `off` is a real disable, including the typed form. Claudetto already uses this key for one name, `skillOverrides: { "plugin-authoring": "name-only" }` (`archive/plugins/claudetto/modules/setup/prompts.ts:144`).
MECHANISM 2, ALL BUNDLED SKILLS AT ONCE: `disableBundledSkills: true`, or `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1`. The same schema says bundled skills and workflows "are removed entirely" while "built-in slash commands stay typable but are hidden from the model". So it stops the model choosing them and does not stop a person typing them. Claudetto already sets it (`archive/plugins/claudetto/modules/setup/prompts.ts:145`), which is why the three bundled skills the user dropped on 2026-10-27 are largely already out.
MECHANISM 3, PER-COMMAND ENVIRONMENT VARIABLE, REACHES 10 COMMANDS: each is a boolean read in `chunk-7srfhct1.js`. See the list below.
MECHANISM 4, A MOD, REACHES EVERY COMMAND: a hook on `command.run` matched to a command name answers instead of running it, and the deny shorthand is `(e)=>({text:e})`. This is the only mechanism that reaches a `local` or `local-jsx` command. It is proven by Anthropic's own published source, not only by the bundle: the `diff` mod hooks `on('command.run', { command: ['clear', 'resume'] }, ...)` at `mods/diff/hooks/register.ts:1020` and `{ command: 'diff' }` at `:876`. The harness derives the plugin's `runCommands` list statically from those matcher literals, so a mod cannot intercept a command it did not name.

THE 37 `prompt` COMMANDS, EACH ONE `skillOverrides` CAN TURN OFF BY NAME: `/artifact-capabilities`, `/artifact-components`, `/artifact-design`, `/artifact-diagramming`, `/batch`, `/claude-api`, `/claude-code-docs`, `/claude-in-chrome`, `/code-review`, `/commit`, `/commit-push-pr`, `/cowork-plugin`, `/dataviz`, `/debug`, `/design`, `/design-sync`, `/doctor`, `/explain-usage`, `/fewer-permission-prompts`, `/init`, `/insights`, `/keybindings-help`, `/loop`, `/memory-types`, `/pr`, `/prototype`, `/run`, `/run-skill-generator`, `/security-review`, `/setup-claude`, `/simplify`, `/statusline`, `/team-onboarding`, `/update-config`, `/verify`, `/workflow-authoring`, `/workshop`.
NOTE ON THAT LIST: six of the ten skills the user dropped on 2026-10-27 are in it, `/debug`, `/fewer-permission-prompts` and `/update-config` as bundled ones, and the claudetto skills `apply`, `archive`, `explore`, `propose`, `sync`, `update` and `verify` are ours and are removed by deleting them, not by a settings key. `/verify` in this list is the bundled one, which is a different page from our own `verify`.

- `/feedback` — `DISABLE_FEEDBACK_COMMAND` (`:18892`). Already set by setup (`docs/surfaces.md:49`). Its registry row shows no gate, so the variable is read somewhere other than the row, and where was not read.
- `/install-github-app` — `DISABLE_INSTALL_GITHUB_APP_COMMAND` (`:18950`), read in the gate. Already set by setup (`docs/surfaces.md:49`).
- `/login` — `DISABLE_LOGIN_COMMAND` (`:19028`), read in the gate.

THE 4 ALREADY OFF IN THIS BUILD: `/loops`, `/pause-memory`, `/version` and `/wellbeing`, each with the gate `isEnabled ()=>!1`. Nothing needs to be set for these.
THE 10 HIDDEN COMMANDS: `/agents` (its description says "(removed)"), `/claim-credit`, `/design-consent`, `/design-revoke`, `/extra-usage`, `/heapdump`, `/limit-reset`, `/low-priority`, `/pro-trial-expired` and `/workflow-launch-exec`. Hidden keeps a command out of the menu. It stays typable where its own gate passes, so hidden is not disabled.

WHAT IS LEFT: the remaining `local` and `local-jsx` commands, which includes every one claudetto cares about keeping or stopping in a session, such as `/clear`, `/compact`, `/context`, `/model`, `/usage`, `/resume`, `/plugin`, `/permissions`, `/rewind`, `/fast` and `/effort`. No settings key disables any of them. A mod's `command.run` hook is the only lever, and it is the lever claudetto already owns, because claudetto is a mod.
WHAT THIS MEANS FOR CLAUDETTO: the goal of keeping a command out of the model's reach is already met for the bundled set by `disableBundledSkills: true`. Stopping a person typing a command needs either `skillOverrides: "<name>": "off"` for one of the 37, or a `command.run` hook for one of the 105. A `command.run` hook is also how claudetto would make a typed `/clear` write a handoff first, which is the gap that group 2 of the `claudetto-restart` change exists to close.
READ ON 2026-10-27, both of them, on `2.1.311`.
- `DISABLE_UPGRADE_COMMAND` does gate its command. `surface slash-command upgrade` gives the row `/upgrade  gate availability claude-ai; isEnabled Kue`, and `Kue()` at `chunk-1qayfjzs.js:179496` is `return!uEt()&&!i.DISABLE_UPGRADE_COMMAND&&sr()!=="enterprise"`. So the earlier note's `isEnabled Iue` was a misreading of `Kue`, and the gate is where it should be.
- `DISABLE_FEEDBACK_COMMAND` does not gate its command. The `/feedback` row at `chunk-r5cyd28m.js:1676485` carries `type`, `name`, `description`, `argumentHint`, `immediate`, and `requires`, with no `isEnabled` and no `isHidden`. The variable is read at `chunk-1qayfjzs.js:199074`, in a function that returns a reason string, `has been disabled via the DISABLE_FEEDBACK_COMMAND environment variable`, beside the same test for `DISABLE_BUG_COMMAND` and for `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`. So the key does not take `/feedback` off the list, it makes the command refuse with that message.
WHAT THAT MEANS FOR THE SETTINGS SNIPPET: `DISABLE_FEEDBACK_COMMAND` at `archive/plugins/claudetto/modules/setup/prompts.ts:121` buys nothing on the model's surface, because a `local-jsx` command is not in the request at all, and it changes only what a person sees after typing `/feedback`. It is therefore a lever with no measured saving, and it goes to the group 11 lever audit for a keep-or-drop decision rather than being removed here. Which of the two paths a typed `/feedback` takes was not probed, because that needs the user's own keyboard.
