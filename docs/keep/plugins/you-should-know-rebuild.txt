`enabledPlugins`, ANSWERED FROM CODE: Yes, a `false` entry does stop a built-in mod, and this is now read in full rather than part-read. `lz()` at `chunk-p9mh7rh2.js:77536` walks `builtinPlugins`, skips any whose availability gate fails, and for each remaining one takes `i = enabledPlugins["<name>@builtin"]` from the settings, then `a = i !== undefined ? i === true : (defaultEnabled ?? true)`. It pushes the plugin onto `enabled` when `a` holds and onto `disabled` when it does not, and only an `enabled` row carries `hooksConfig` and `hooksModule` forward. COST OF ONE CHECK, THE RULE THAT FOLLOWS FROM THE CLIFF: The whole call, the cached block and the digest together, must stay under `100,000` prompt tokens, because the page states that the threshold "counts all of its input tokens, including cache reads and cache writes" and that a request over it "pays the higher prices even when part of its prompt is a cache hit". So the cached fixed block does not shelter the call, and crossing the line reprices the whole request at five times rather than only the excess. A bounded digest keeps the call far from the line by construction, which is a second reason to build one rather than to fork the window, since a forked window carries the whole session and would cross `100k` in a long session on its own.
