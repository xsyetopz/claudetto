
# Dossiers 2026-09-29 to 2026-10-01: agent models, effort, and turn limits

## Sources

The dossiers are exports of Reddit threads from `r/ClaudeAI` and `r/ClaudeCode`, from 2026-09-28 to 2026-10-01.
They hold user reports, a few user benchmarks, and quotes of Anthropic pages.
Anthropic pages are cited here as quoted in a thread, so the quote is second hand.
The summary file in `summaries/` is a `/context` dump of a Claude Code session and has no bearing on the goal.
Main sources:

- Anthropic, "Introducing Claude Sonnet 5.5" (anthropic.com/claude-sonnet-5-5), quoted in the `r/ClaudeCode` post "Introducing Claude Sonnet 5.5, the second model in the Claude 5.5 family".
- Anthropic, "Optimizing for cost and intelligence" (platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence), quoted in the `r/ClaudeAI` thread "PSA: you don't need Fable for everything. Set it as your advisor instead".
- Anthropic, "Claude Opus 5.5 prompting guide", as summarized in the `r/ClaudeAI` thread "Claude Opus 5.5 official prompting guide".
- `r/ClaudeAI` post "Sonnet 5.5 vs Opus 5.5: the Terminal-Bench win is Max vs Xhigh. Here's the fair comparison", which quotes the Anthropic launch table.
- `r/ClaudeAI` thread "Sonnet 5.5 has been out for an hour", comment by `fuzzypetiolesguy` (90 test runs).
- `r/ClaudeAI` post "Sonnet 5.5 vs Opus 5.5 on a from-scratch Rust decompressor".
- `r/ClaudeAI` post "Sonnet 5.5 vs Opus 5.5 vs Sonnet 5 in Claude Code and pi" (10 tasks, 3 runs each).
- `r/ClaudeCode` post "I benchmarked a 30-line Claude Code plugin on Opus 5.5 and Sonnet 5.5".
- `r/ClaudeAI` post "Measured it: headless Claude Code eats ~3x more of the 5-hour limit per token".

## Findings

### Model choice per task

Anthropic says Sonnet 5.5 is "strongest at well-scoped everyday tasks, fixing bugs, and creating polished documents".
Source: the Anthropic launch post, quoted in the Sonnet 5.5 launch thread.
Sonnet 5.5 costs $2/$10 per million tokens, Opus 5.5 costs $4/$20.
Source: the Terminal-Bench thread, which cites TechCrunch (2026-09-28).
The launch table shows a tie on knowledge work and computer use, and an Opus lead on harder coding.
FrontierCode 1.1 is 46.2% for Sonnet and 54.4% for Opus.
Terminal-Bench 4.0 at the same `xhigh` effort is 61.5% for Sonnet and 66.4% for Opus.
The "Sonnet beats Opus" headline compares Sonnet at `max` with Opus at `xhigh`.
Source: the Terminal-Bench thread above.
A user test of 35 bug-fix tasks with hidden tests gave 34 fixes for Opus and 34 for Sonnet.
Sonnet was 22% faster and left its assigned folder in 4 of 35 runs, Opus in 0.
The same user planted 33 errors for a proofreader role.
Sonnet caught 33, Haiku caught 29 with 3 false alarms and 4 wrong lines.
Source: the "out for an hour" thread.
This is Haiku 4.5, not Haiku 5.5.
Haiku 5.5 was announced "in the coming weeks", so no 5.5 Haiku data exists in these dossiers.
A single Rust DEFLATE task at `medium` effort: both models passed all 4055 hidden tests.
Opus took $2.08 in 10m18s and Sonnet $0.52 in 3m41s, and Opus won on polish, not correctness.
Source: the Rust decompressor post.
A 10-task, 3-run test at `high` effort in Claude Code: both passed 30/30.
Sonnet took 53s and about $0.15 per task, Opus took 108s and about $0.36.
Source: the "Sonnet 5.5 vs Opus 5.5 vs Sonnet 5" post.
The same post reports that Sonnet 5.5 cut turns from 12.7 to 4 against Sonnet 5, and that it read files in batches through `bash`.
A Haiku 4.5 report in the "When and what do you use Haiku for" thread says Haiku tied Sonnet 4.6 on 1-2 command tasks.
On tasks of over 40 commands it finished 21% against 79%.
Source: a comment that links an `r/ClaudeAI` post on Haiku and SWE-bench.

### Effort

The Opus 5.5 prompting guide says effort is "the main dial".
It says `medium` is the default and matches or beats Opus 5 at `high`.
It says lowering effort cuts thinking more reliably than prompt text.
Source: the summary in the "official prompting guide" thread.
The same thread quotes the guide: a change of the top-level effort between requests invalidates the prompt cache.
A per-message effort change (beta) keeps the cache.
This matters for a subagent that has its own effort, since each subagent has its own cache.
The Artificial Analysis cost chart used `max` effort and made Sonnet look costly.
At `low` and `medium` Sonnet is cheaper, and at `max` Opus 5.5 is cheaper per task.
Sources: the threads "Sonnet 5.5 is great and all but where to use it" and "Sonnet 5.5 has the same problem as Sonnet 5".
One report says Sonnet 5.5 needs 193k output tokens per task at `max`, against $7.60 for Sonnet and $5.98 for Opus 5.5 `max`.
Users advise `medium` as the default and `max` almost never ("How do you guys know how much effort to use" thread).
These are opinions, not measurements.

### Subagents, advisor, and orchestration

The most common pattern in the threads is one Opus root session that sends Sonnet workers for scoped work and Haiku for search.
Source: the "out for an hour" thread, whose moderator summary names Opus as orchestrator and Sonnet as worker.
Users report that Sonnet 5.5 fits "tightly bounded implementation" and is a poor driver.
Source: comments in "Sonnet 5.5 has the same problem as Sonnet 5".
One user found Sonnet 5.5 too critical as a reviewer, with no convergence in 24 hours.
Source: a comment in "Where does Sonnet 5.5 actually fit into your agent stack".
The Anthropic cost guide, as quoted, measured an advisor setup.
Opus 5.5 at `high` with a Fable/Mythos 5.1 advisor scored 90.1% at $2.92 per attempt.
That is 1.7 points over Opus alone, a gap "at the edge of run-to-run noise", for about 2.1 times the cost.
Opus 5.5 alone at `xhigh` scored 91.1% for $4.11.
The guide says the advisor fits poorly when the executor is close to the advisor in capability.
Source: the "PSA: you don't need Fable for everything" thread.

### Multi-agent cost

Users report that subagents raise cost when they are many or careless.
Examples: "excessive and careless subagent use" ends a plan early, and each subagent "needs to have its own context".
Sources: comments in "Can Claude Pro $20 plan will be enough for me" and "What is wrong with Opus 5.5 all of a sudden".
One user says a subagent cache TTL is shorter than the main session cache TTL.
A user who lowered Fable/Mythos use from 80% to 40% told the top model to read only concise subagent reports and to verify with a test.
Source: the thread "With Fable 5.1 being my main driver I kept hitting 80%".
The headless measurement found `claude -p` used 5.2% of the 5-hour limit per $1, against 1.7% for interactive use.
Claude Code 2.1.277+ gives a "wrap-up allowance" at the 5-hour limit.
The note tells the model to finish the step, list what is left, and not start subagents.
Source: a comment in "Claude can't see its own limits or context".

### Turn limits

No thread discusses `maxTurns` or a subagent turn cap.
The nearest evidence is indirect.
Users report stuck loops, such as a delegated agent that "retried it way too many times" on a race condition ("How do you guys know how much effort to use" thread).
The prompting guide, as summarized, says time budgets such as "elapsed 340s / 1200s" make agent teams pace themselves.
It also says unattended agents can end a turn on a progress update.
Source: the "official prompting guide" thread.

## Implications for the dotclaude agents

- The Opus and Sonnet split fits the evidence: Opus for plans and reviews, Sonnet for scoped work.
- Sonnet 5.5 at `medium` or `high` for `implementer` is supported by three user tests, all on well-scoped tasks.
- Sonnet for `debugger` at `high` is weakly supported, since the sources say Opus leads on messy and open-ended debugging.
- Sonnet as `reviewer` has one negative report, and Opus has the benchmark lead on hard coding.
- Haiku 5.5 for `investigator` has no data here, only Haiku 4.5 reports of good search and poor long tasks.
- A fail-safe is to keep Sonnet 5.5 `low` or `medium` as the fallback until Haiku 5.5 data exists.
- Avoid `max` and `xhigh` on subagents, since thinking dominates cost at `max`.
- Lead the agent prompt with a scope rule, since Sonnet 5.5 left its folder in 4 of 35 runs.
- Tell each subagent to return a short report, because the parent pays to read it.
- A Fable/Mythos subagent is not supported: the data shows no gain over Opus at about twice the cost.
- A `maxTurns` limit has no direct evidence in these dossiers.
- Turns fell from 12.7 to 4 for Sonnet 5.5 in one test, and thinking at high effort adds turns, so a value of 31 to 61 is far above typical use.
- A limit then acts only as a stop for stuck loops, and the agent should return its partial result at the limit.
