|---|---|---|

| `__SYSTEM_PROMPT_DYNAMIC_BOUNDARY__` line marks the cache boundary | run | cited |

| No settings key sets the prompt | n/a | observed (`surface setting-key prompt`) |

Default `system` size: Opus 5.5 6,274 bytes, Sonnet 5.5 about 6.0k, Haiku 5.5 8,862 (observed). Tools were 29,666 bytes in each request (observed). The docs give short-prompt sizes of 5,776, 5,586, and 8,429 chars, and about 27k for the full prompt that older models get.

A plugin cannot replace the system prompt outright. It can rewrite sections through a `prompt.compose` mod, add an output style, or ship an agent.

## Per-Model Prompt

No declarative per-model key exists. The routes:

- Mod `prompt.compose`, input `model`: per-request, per-model rewrite (cited; live run pending in `probes.md`).
- `$.session.model()` inside `prompt.section` (cited).
- `SessionStart` hook input `model?` was absent in a `-p` start (observed), so do not rely on it.
- `PreModelSwitch` and `PostModelSwitch` give `from_model` and `to_model`; `PostModelSwitch` can add `additionalContext` (cited).
- Mod `agent.spawn`: `parentModel` (read-only), and `model` and `prompt` are rewritable (cited).
- Agent frontmatter `model`, with the body as prompt (cited).
- `modelSettings.<model>.{effortLevel,maxEffortLevel,autoCompactWindow}` sets values only, not prompts.
- Output styles do not reach subagents.

## Subagents

- Frontmatter fields: `name`, `description`, `tools`, `disallowedTools`, `model`, `permissionMode`, `maxTurns`, `autoCompactWindow`, `skills` (at most 32), `mcpServers`, `hooks`, `memory`, `background`, `omitClaudeMd`, `effort`, `isolation` (`worktree`, `remote`), `color`, `initialPrompt`, `experimental.cacheTtl`.
- Plugin agents ignore `permissionMode`, `hooks`, `mcpServers`, and `initialPrompt`.
- Keys are camelCase and case-sensitive.
- Model order: the per-call model, then frontmatter, then `CLAUDE_CODE_SUBAGENT_MODEL`, then the main model.
- A subagent gets no output style and no auto memory. It gets `CLAUDE.md` unless `omitClaudeMd` is set.
- Built-ins: `Explore`, `Plan`, `general-purpose`, `claude`, `statusline-setup`, `claude-code-guide`, `fork`. A same-named user agent replaces one. `permissions.deny Agent(name)` and `CLAUDE_CODE_DISABLE_EXPLORE_PLAN_AGENTS=1` disable them.
- Limits: `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` (3), `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` (20), and `CLAUDE_CODE_SUBAGENT_MODEL` with `_FORCE`.
- A skill can run as a subagent through `context: fork` plus `agent:`.

## Plugin Surfaces

- 33 hook events. Blocking ones: `PreToolUse`, `UserPromptSubmit`, `UserPromptExpansion`, `PostToolBatch`, `Stop`, `SubagentStop`, `TeammateIdle`, `TaskCreated`, `TaskCompleted`, `ConfigChange`, `PreCompact`, `PreModelSwitch`, `Elicitation`, `ElicitationResult`, `WorktreeCreate`, `WorktreeRemove`.
- Handler types: `command`, `http`, `mcp_tool`, `prompt`, `agent`.
- Mod API: about 90 `$` calls and about 80 events in five tiers. `disableAllHooks`, `--safe-mode`, and `--bare` load no mods, and a server flag gates the rollout.
- Skill frontmatter for light loading: `disable-model-invocation`, `user-invocable`, `paths`, `allowed-tools`, `model`, `effort`, `context: fork`.
- A plugin can ship `skills`, `commands`, `agents`, `hooks`, `mcpServers`, `outputStyles`, `bin/`, `userConfig`, and `settings`. Of `settings`, only `agent` (deprecated) and `subagentStatusLine` (no effect) take effect.
