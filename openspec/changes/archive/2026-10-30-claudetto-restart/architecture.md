## Components

One plugin, `claudetto`, built as a mod plus static files. The mod is `plugins/claudetto/hooks/hooks.json` `modules` pointing at one `register.ts`. The static files are agents, skills, and the output style. Each capability is one small module of one concern. Claude Code `2.1.312` is the target, which is the installed version since 2026-10-27, so each check of this change runs on it. A row read in an earlier version keeps the version it was read in, because a `chunk-*.js` name is per build.

| Component | Job | Surface (verified in the installed `2.1.311`, unless the row names another) |
| --- | --- | --- |
| `tiers` | One table per subscription tier: subagent cap, subagent model, main model and effort, context cap, handoff threshold, tool-describe set | Setup writes `env` and settings keys. The tier comes from `.claude.json` via `archive/plugins/claudetto/modules/setup/domain/plan.ts` |
| `handoff` | Writes a short handoff before context is lost. Replays it in the next session | `classic.PreCompact`, `classic.PostCompact`, `classic.SessionEnd` (reason `clear`, `resume`, `logout`, `prompt_input_exit`, `other`), mod events `session.end`, `session.compact`, and `classic.SessionStart` (`source` `clear`, `resume`, `fork`) |
| `compaction` | Sets compaction instructions, and later the winning path of the probe | `session.compact`, `$.session.compact`, a `PreCompact` stdout line goes to the compaction prompt as additional instructions |
| `prompt-trim` | Cuts the session prompt and tool texts, with a size budget | `prompt.compose`, `prompt.section`, `tool.describe`, `prompt.attachment`, `prompt.context` |
| `run-limits` | Caps subagent depth and starts, ends stuck agents, reports background tasks at Stop | `agent.offer`, `agent.spawn`, `classic.SubagentStart`, `classic.SubagentStop`, `classic.Stop` |
| `auto-mode` and `permission-policy` | A curated rule set. A fixed verdict for safe calls before the classifier. Fail closed for an ungated `PermissionRequest` | `tool.check`, `classic.PermissionRequest`, `classic.PermissionDenied`, `autoMode` setting |
| `status-line` | A `statusLine` command that reads stdin JSON only | `statusLine` setting |
| `workflow-skills` | Skills that call the `openspec` CLI with the `epic`, `story`, `task` schemas | `openspec/schemas/` |
| `setup` | One CLI, not a skill, that merges a documented settings snippet by tier. The user decided on 2026-10-30 to ship it as a CLI because a CLI costs zero prompt characters | `plugins/claudetto/src/tiers/setup.ts`, `just setup` |

Added for the window goal: `window-budget` records window points per turn and per task. Surface: `session.measure` (fires after each main-thread turn and when a rate-limit window moves a whole point) and `$.session.usage()` (returns `rateLimits` with `five_hour` and `seven_day`, per the `clawdipedia` pages `extend/mod-api/session` and `extend/mod-api/types/session`). The windows exist for Claude.ai Pro and Max only (`configure/status-line`: `rate_limits.five_hour` and `.seven_day`, `used_percentage` and `resets_at`). An API-key login records dollars.

Dropped, because a built-in covers them (from the earlier plan `epic-a-complete-restart-sunny-conway.md`, not re-checked one by one): the old handoff timer queue, `work/finish`, `work/protect`, the ledger and hygiene, `work/notes`, `work/ground`, the `work/reply` judge, and the `claudetto-browser` plugin and `find-docs` skill, which hard-code `agent-browser` and Context7. For `find-docs` the reason "a built-in covers them" does not hold on its own, since no built-in tool fetches library docs and only `WebSearch` and `WebFetch` come near it. ## Data and Interfaces

- Mod stores: `$.store` for the decision record and the tier cache, `$.state` for a pending resume. No private file unless the Mod API has no store. The mod API has `$.store.get/set/delete/keys`, `$.state.get/set`, `$.fs.*`, `$.session.usage/messages/compact/send`, `$.model.complete/classify/fork`, `$.clock.after/every`, and `$.command.run` (checked with `cc-inspect` `surface` `mod-api`, 231 items).
- Handoff file: `.claude/claudetto/handoffs/handoff-<UTC stamp>.md`, path from `archive/plugins/claudetto/modules/project/domain/paths.ts`. It holds the goal, the open task, the files touched, the decisions with their reasons, and the pinned versions. A thread reported that a handoff dropped a pinned API version, so pinned versions are a fixed field. Another reported that a note written at a full window forgets a "do not touch" file, so the writer runs at a lower threshold than the window.
- Handoff read-back: `classic.SessionStart` with `source` `clear` or `resume` reads the newest handoff file, if none is pending in `$.state`, and injects it once.
- Tier table row: `{ tier, subagentCap, subagentModel, mainModel, effort, contextCap, handoffTokens, describeSet }`. Written to `env` (`CLAUDE_CODE_SUBAGENT_MODEL`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`) and settings (`model`, `autoCompactWindow`). `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` is verified in the installed binary (`references.md`, "Dossier Measured Items"). `CLAUDE_CODE_SUBAGENT_MODEL` and `CLAUDE_CODE_AUTO_COMPACT_WINDOW` are documented (`clawdipedia` routes `extend/subagents/frontmatter` and `how-it-works/context-and-compaction`), and the binary check is task 8.3. The two compaction names are not alternatives. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` sets the window in tokens (it is first in the lookup order, before the `autoCompactWindow` setting), and `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` sets `pct`, so the threshold is the smaller of `effective * pct / 100` and `effective - 13000` (`how-it-works/context-and-compaction`). Which of them a row writes is decided by the pin test of task 8.3. The subagent cap has no verified key. `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` did not match in the binary, so it is not used (`references.md`, "Dossier Measured Items"). `CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION` and `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` exist and their meaning is unread, which `archive/tasks.md`, old task 11.5 reads. Until then `subagentCap` is held by the `agent.spawn` hook of `run-limits`, and its value is the code value of `design.md`.
- Compaction env vars in the binary that the plan has not yet read: `CLAUDE_CODE_COLD_COMPACT`, `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, `CLAUDE_CODE_SLEEP_COMPACT`, `CLAUDE_CODE_SLEEP_COMPACT_AFTER_MS`, `CLAUDE_CODE_DISABLE_PRECOMPACT_SKIP`, `DISABLE_AUTO_COMPACT`, `DISABLE_COMPACT`. A reading of the installed version settles them all, including `CLAUDE_CODE_COLD_COMPACT` and `CLAUDE_CODE_SLEEP_COMPACT`.
- Session end: the mod event `session.end` fires once on exit, `/clear`, resume, logout, signal, or a finished `-p` run, after the `SessionEnd` settings hooks. The whole chain shares one short time bound that `next.budget` reads (`clawdipedia` page `extend/mod-api/session`). So the end writer cannot call a model. `$.session.messages` returns at most 4096 entries. Whether it still answers at `session.end` is not documented, and `archive/tasks.md`, old task 2.1 probes it.
- Window rows in `$.store`, as built: two series, because one event does not carry both halves. `window.rows` holds a `session.measure` row `{ at, task, source, tokens, window, percent, points, usd }`, where `tokens` is the whole prompt of the last response and so carries no output count and no cache split, and `window.turns` holds a `turn.complete` row `{ at, turn, task, source, model, inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens }`. `source` is `main`, `subagent`, `compaction`, `handoff`, or `classifier`. A row is dropped once it is older than the seven-day window. The weight is the points of the measure rows over the input-side tokens of the turn rows, with no minimum row count: a figure prints with the count of turns it rests on beside it, since a threshold would be a number with nothing behind it. The fit stays open; `archive/tasks.md`, old task 9.3 read Botfarm and `claude-hud` and found no method to copy, and `design.md`, "Window Budget" states all of this with its line numbers.
- Measured prompt text, in characters, from `bun` over `archive/plugins/claudetto/modules/session/prompt/prompts.ts` on 2026-10-27: tool texts `TOOL_AGENT` 814, `TOOL_BASH` 1535, `TOOL_EDIT` 301, `TOOL_ENTER_WORKTREE` 1498, `TOOL_EXIT_WORKTREE` 1025, `TOOL_READ` 545, `TOOL_SEND_MESSAGE` 2096, `TOOL_SKILL` 1068, `TOOL_TOOL_SEARCH` 613, `TOOL_WRITE` 261, total 9756. Lines: `PRECOMPACT_LINE` 190, `TURN_LIMIT_LINE` 106, `SHELL_MACOS` 140, `SHELL_ZSH` 137, `CONTEXT_MANAGEMENT_*` 88 to 137. Not yet compared with the built-in text of the same tools (`clawdipedia` page `prompts/tools` holds those), so whether the rewrite is shorter than the original is unknown. Task 2.6 compares them.

## Constraints

- No patch of the Claude Code binary or npm package. Reading the bundle for evidence is allowed (`AGENTS.md`).
- Use only documented or probed `2.1.312` surfaces. A pin test guards each undocumented key (the rule in `.claude/rules/claude-code.md` of the earlier plan, now deleted in the working tree, so the pin test itself carries the rule).
- Cache stability: a prompt edit is a pure function of its inputs. No time, counter, or usage number in a shared section. Evidence: a model switch wipes the cache (`clawdipedia` route `how-it-works/request-and-cache`), a tool call over 5 minutes with the default 5-minute TTL re-writes the whole context (one measured self-report), and an idle gap past the TTL does the same. This is now the highest-value constraint in the change, by our own measurement rather than by argument: cache writes are 49.8% of the cost of this machine's 80 transcripts at Anthropic's official prices, the largest single line, while being 5.21% of its tokens (`archive/tasks.md`, old task 9.2b, `references.md`).
- No per-message injection. Context goes in once, at `prompt.context` or `session.compact`. Today the usage line is added on a band change only, through `classic.UserPromptSubmit`.
- A hard size limit for added prompt text, checked by test (`archive/plugins/claudetto/tests/prompt-size.test.ts` is the model: bound `PROMPT_SIZE_MAX_CHARS` = 40,000 in `archive/plugins/claudetto/modules/session/prompt/limits.ts`).
- A source file has at most 300 lines and a test file at most 500 (`AGENTS.md` of the user rules).
- No wiki step in `just check`. The paid probe waits for user approval, and its cost is given as a share of the weekly limit. Any weekly-share figure with no source is under "Held Back until Sourced" in `prd.md`.
- Prices that bound the compaction choice (live read of `platform.claude.com/docs/en/build-with-claude/prompt-caching`, Pricing section, per MTok): Opus 5.5 input $4, 5m write $5, 1h write $8, cache hit $0.20, output $20. Sonnet 5.5: $2, $2.50, $4, $0.10, $10. Haiku 5.5 for prompts up to 100,000 tokens: $0.10, $0.125, $0.20, $0.01, $0.50. Haiku 5.5 for prompts over 100,000 tokens: $0.50, $0.625, $1, $0.05, $2.50. A cache hit on Opus 5.5 and Sonnet 5.5 is 0.05x base input.
- Three cache claims bear on the compaction choice. First, a forked compaction reuses the parent prefix at the cache-hit price (verified on 2026-10-27 with a condition, `archive/tasks.md`, old task 8.4). The Mod API type `ModelUsage.cache_read_input_tokens` is documented as "On a fork, how much of the main thread's transcript the cache still held: near zero, the fork paid for the whole prefix (the entry had lapsed, or the model changed since it was made)" (`clawdipedia` route `extend/mod-api/types/model`). So the reuse holds while the entry is live and the model is the same, and it fails on a model switch, which the same route's "Switch model, Full miss" row states (`how-it-works/request-and-cache`). The entry a fork writes lasts 5 minutes, not the 1 hour of the main conversation of a subscriber ("Subagents, workflows, forks, compaction, and titles", same page), so a fork of a cheap model pays the full input price of the whole prefix, which is the case this design weighs. Second, a separate summarizer call with its own system prompt gets no cache hit (verified on 2026-10-27, `archive/tasks.md`, old task 8.4). The API reads a request as tools, then system, then messages, and "A change in an early part makes the later parts miss the cache" (`how-it-works/request-and-cache`), while a cache mark is read only by "a call within five minutes that opens with the same text" and "Both zero means nothing was cached" (`ModelTextBlock.cache`, `extend/mod-api/types/model`). A `$.model.complete` call carries its own system prompt and one user message, so it does not open with the session's prefix and reads none of it. Third, a mid-session model switch rebuilds the cache. The third is documented: "Switch model ... Full miss" and "each model has its own cache" (`clawdipedia` route `how-it-works/request-and-cache`). The earlier trace to a Claude Code team post of 2026-04-30 (read by a web agent) is not the source. If the first two hold, a cheap-model handover pays full input price on the whole context. Example, proposed: a 200k-token context costs about $0.04 as an Opus 5.5 cache hit, and about $0.10 as an uncached Haiku 5.5 input over the 100,000-token tier, before output. The probe must price this, and a handoff built by code with no model call is the arm to beat.
- Cache invalidators per the docs, as the web agent read them: model switch, effort change on older models, fast mode toggle, tool-definition change with tool search off, compaction, images, upgrades. Skill invocation, plan mode, and `/rewind` keep the cache.
- Not confirmed anywhere: whether cache reads count against the plan limits, and at what weight. No source gives per-tier quotas. Cost is therefore measured in API-equivalent dollars and in the `/usage` share, and never promised as a plan share.
- Tool lists stay short. The article reports tool choice degrading past 30 to 50 definitions. The `/context` baseline has system tools 5.9k plus deferred 4.5k, so deferral is already on for part of the set. That reading is a lower bound, because `/context` under-counts tools (see `prd.md`), and the per-tool character counts in `docs/levers.md` are the figures to act on.

## Decisions

- D1: Handoff first, compaction by measurement. Why: a typed `/clear` is the proven loss, and one thread claims a small handoff beats a 64k-token autocompact write (opinion). The repo probe shows no winner, so the choice waits on the cheap-model probe. Alternative: built-in compaction only, with a `session.compact` hook (the earlier plan's Q4, answered by Jev with no dialog, so it is reopened).
- D2: Write the handoff at `SessionEnd` with reason `clear`, and at `PreCompact`. Why: no other hook runs before a typed `/clear`. Alternative: a Stop-time trigger on a token threshold only, which is today's design and misses `/clear`. Each is verified to exist in `2.1.311`, and task 4.3 measured the interactive case in a real REPL of `2.1.312` (`references.md`, "The Interactive `/clear`, Measured in the REPL"). On a typed `/clear` both halves of `SessionEnd` run with the session still bound: `$.fs.write` works and `$.session.messages()` answers with the whole conversation, in the classic hook and in the Mod API handler alike, while on `prompt_input_exit` both throw "no session is bound". That is the prediction the binary gave, and the exit reason is the contrast that shows it is the binding and not the phase. The writer still reads `transcript_path`, which is no longer a fallback but the one source every path has: the exit reasons, a `-p` run, and `PreCompact`. Three constraints come with it. A `function`-type hook must not be declared for `SessionEnd`. The mod handler's bound is `DHe()`, measured as 1,500 ms, while the classic hooks get `H2s()`, also 1,500 ms unless `CLAUDE_CODE_SESSIONEND_HOOKS_TIMEOUT_MS` is set. And `next.budget.remainingMs` reports 10,000 in the classic chain while the cut lands at 1,500, so the writer takes the smaller of the two and never the reported figure.
- D3: A tier table in code, not one snippet for all. Why: usage limits differ by tier, and threads report different failure points (Pro runs out in 2 to 3 days of free use, 5x fills the weekly first, 20x re-read cost 23%). Alternative: user-chosen profile only.
- D4: Subagents fold into the main loop for short coupled work, and stay for large reads and parallel jobs. Why: the article, and measured cold-start re-reads. Subagent models come from the tier row through `CLAUDE_CODE_SUBAGENT_MODEL`, not fixed IDs in agent files. Alternative: keep the current fixed Sonnet and Haiku agents.
- D5: End stuck agents by rule (an hour with no file change, or a loop) and cap starts per window. The definition of "stuck" and its limits are in `design.md`, "Run Limits", and the rule is not decided here. Why: one self-report of a drop from over 30% to under 10%, where the author calls "stuck" an hour or more with no real changes, or a loop (`external/2026-10-27/reddit.com-r-claudeai-comments-1xeozdj-usage-cap-advice-for-the-nontech-20261026T132736Z.md`, lines 33 and 90), which is not a measurement, and a 394-agent, 84M-token run in 10 minutes recorded in the earlier plan.
- D6: Prompt text is cut by `prompt.compose` and `tool.describe`, with a byte budget per piece. Why: the article reports an over 80% cut in Claude Code's own prompt. Alternative: `--system-prompt` replacement, rejected because it loses the cache-friendly section order.
- D7: No wiki. Probe evidence is one plain Markdown file under `docs/`. Why: the user deleted the wiki and called its upkeep annoying.
- D8: Keep the subagent 1-hour cache and any keepalive as an option per tier, not a default. Why: the one measured self-report says tokens rise slightly and only billing shifts, and a keepalive on a stuck agent keeps billing. The documented key is `subagentPromptCacheTtl` or `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` (`5m` or `1h`), as the web agent read it from the Claude Code docs. Re-check it with `clawdipedia` before use.
- D9: Do not set `CLAUDE_CODE_PROMPT_CACHE_TTL` to `1h` for subscription tiers. Why: the web agent read in the Claude Code docs that the main conversation already defaults to one hour on a Claude subscription, and to five minutes with usage credits, an API key, or a cloud provider. Setup writes the key today, at `archive/plugins/claudetto/modules/setup/prompts.ts:100` (read 2026-10-27). Re-checked with `clawdipedia` on 2026-10-27 and confirmed: the `configure/settings/model` page of the `2.1.311` docs says of `promptCacheTtl` that "Unset is 1 hour on a subscription and 5 minutes on an API key or cloud provider", and that `CLAUDE_CODE_PROMPT_CACHE_TTL` wins over the setting. So the line is a no-op on a subscription and forces the costlier 1-hour write on an API key or a cloud provider. Task 8.5 removes it.
- D10: Agent files carry no `model:` line. Why: per `clawdipedia` route `extend/subagents/frontmatter` (row `model`, checked 2026-10-27), the order is the per-invocation `model`, then the agent frontmatter, then `CLAUDE_CODE_SUBAGENT_MODEL`, then the main model. A fixed `model:` in `agents/*.md` beats the tier value, so the tier table could not steer those agents. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE` is the alternative and is rejected, because it also overrides a deliberate per-call model.
- D11: Skills with no model use set `disable-model-invocation: true`. Why: `clawdipedia` route `extend/skills-and-commands/substitutions` says that with `disable-model-invocation: true` "The description is not in context" (checked 2026-10-27), and by default "The description is always in context". Ten skill descriptions (155 to 194 characters per `description:` line, 1,720 in all, counted 2026-10-27 over `archive/plugins/claudetto/skills/*/SKILL.md`) load every session now. This count replaces the earlier eleven of the Apollo run.
- D13: Measure the window, do not guess it. Why: Anthropic publishes no per-tier quota and no weight for a cache read against a plan limit (the web agent found none), yet the mod receives the window percentage after each turn. Rows from this login answer both questions, and they show the effect of every other decision in this change in the unit the user pays in. Alternative: trust thread numbers, rejected because they are self-reports and one author's own edit says billing shifted and tokens did not fall.
- D14: The handoff writer is code and runs inside the `session.end` bound. Why: a model call cannot finish in that bound, and the model call also loses the cache. The rolling file after a changed turn covers a killed terminal, which no end hook sees. Alternative: a model summary at end, rejected for both reasons.
- D15: Rank the levers by the cost mix, not the token mix. The line that each task group pulls, with its share, is the table "Which Cost Line Each Group Pulls" in `prd.md`, which `archive/tasks.md`, old task 9.2c wrote from this decision. Why: the two point opposite ways on our own data (`archive/tasks.md`, old task 9.2b). Of the cost of this machine's 80 transcripts, priced at Anthropic's official rates, cache writes are 49.8%, output 28.2%, and cache reads 22.0%, while of its tokens cache reads are 93.67%, cache writes 5.21%, and output 1.12%. So the order of work is cache stability first, then output volume, which is the effort level and the agent roster, then the prefix trim of groups 2 and 3. The trim keeps its place because a prefix character is re-read about 18 times for each time it is written, measured as the write to read ratio here, but it is pulling the 22.0% line and not the 93.67% one. Alternative, rejected: keep the dossier's framing that cache reads are the bill, which is true of tokens and false of cost, and which would have put groups 2 and 3 first. Caveat: this login is a Max 20x subscription, so no dollar was billed, and the dollars are what the same tokens would cost on the API, used as a proxy for the plan share per the constraint above. `claude-opus-5` is 36.8% of the tokens and is excluded from the mix, because no per-category price for it was read. `/usage` later gave its total cost for one session directly, `$65.66` of `$102.71`, at a blended `$0.80` per MTok against `$0.35` for `claude-sonnet-5-5`, so the excluded traffic was dearer per token than the traffic that was priced, and the mix understates the total. Second caveat, which qualifies "cache stability first": the two `/usage` readings show 5 expected rebuilds against 1 miss over 596 main-thread requests, attributed by the screen to "compaction or tool-result clearing". So on this machine the 49.8% write line is driven more by when a compaction happens, which is group 10 and group 4, than by a changing prefix, which is group 2. The screen gives no token count per rebuild, so the event count does not re-rank the groups by dollars, and the prefix rule stays, because a miss re-cached `233.0k` tokens at about `$0.93`.
- D16: The Haiku prompt cap is a hard requirement of correctness, not a tuning value. Why: Anthropic's pricing page states that a Haiku 5.5 request whose prompt is over 100,000 tokens is repriced five times on the whole request, that the prompt length "counts all of its input tokens, including cache reads and cache writes", and that each request is priced on its own (read 2026-10-27, quoted in `docs/models.md`). Cache reads are 93.67% of tokens here, so a cached prefix does not shelter a request from the cliff, it is most of what pushes it over. Alternative, rejected: treat the cliff as a soft budget, which the earlier note allowed while the whole-request reading was still `self-report`.
- D12: Idle compaction stays off by default and becomes a tier option (`idleCompaction`, `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`). Both are marked Documented in the `clawdipedia` search. The docs say an unset size "uses a built-in default", so the default is read from the binary before use.
