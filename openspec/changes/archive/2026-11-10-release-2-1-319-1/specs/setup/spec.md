## ADDED Requirements

### Requirement: A Starter Memory File for a Repo with None

`/claudetto:setup` SHALL plan starter files from marker files that git lists (tracked, or untracked and not ignored) in the project folder, with no model call. A marker is a root name or `*` glob, an exact path, or a `dir/` prefix, and a marker below the root SHALL NOT count. It SHALL plan `AGENTS.md` and a `CLAUDE.md` of a title, a blank line, and `@AGENTS.md`, and only when the folder holds neither file. No file SHALL be planned when no family is known.

#### Scenario: A Bun Repo

- **WHEN** the folder has `package.json` and `bun.lock` and no memory file
- **THEN** setup plans `AGENTS.md` with bounded commands and a `CLAUDE.md` that imports it (`hooks/setup/starter.test.ts`, "a bun repo gets bounded commands from its markers", "CLAUDE.md is a title, a blank line, and the import")

#### Scenario: A Memory File Exists

- **WHEN** the folder holds `AGENTS.md` or `CLAUDE.md`
- **THEN** no starter file is planned ("an existing AGENTS.md or CLAUDE.md plans nothing")

### Requirement: A Planned Starter File That Exists at Write Time Is Kept

A file that exists at write time SHALL be left as it is.

#### Scenario: A File Appears Before the Write

- **WHEN** the user answers Write and a planned file now exists
- **THEN** it is left as it is and the report says so (`hooks/setup.test.ts`, "a file that appears after the starter question is not overwritten")

### Requirement: The Starter AGENTS.md Holds Bounded Commands

`AGENTS.md` SHALL hold one line per test, build, lint, and type check command of each detected family, labelled by family when more than one is found, and SHALL be cut at 600 characters.

#### Scenario: Two Stacks

- **WHEN** the folder holds markers of two families
- **THEN** both are named, in table order (`starter.test.ts`, "a repo with two stacks names both, in table order")

### Requirement: Ignore Files Carry One Marked Block

Setup SHALL write one marked block, opened by `# >>> claudetto: generated by /claudetto:setup, edit outside this block` and closed by `# <<< claudetto`, into `.gitignore` and `.ignore` of a git work tree, and SHALL touch no line outside it. A folder outside a git work tree SHALL be offered nothing. `.rgignore` SHALL never be made.

#### Scenario: Not a Git Work Tree

- **WHEN** the folder is outside a git work tree
- **THEN** setup offers no ignore file

### Requirement: The Ignore Block Holds Fixed and Heavy Paths

`.gitignore` SHALL get the fixed lines `.DS_Store`, `Thumbs.db`, `*.swp`, `.claude/settings.local.json`, `.claude/worktrees/`, `.claude/claudetto/`, and `CLAUDE.local.md`, and each heavy path of a detected family that git does not track. `.ignore` SHALL get each heavy path that git tracks and each bulky path that git lists, and SHALL NOT be made when it would hold nothing.

#### Scenario: No Ignore File

- **WHEN** the repo has no `.gitignore` or `.ignore`
- **THEN** `.gitignore` is made as the block, and `.ignore` only when it would hold a line (`hooks/setup/ignore-plan.test.ts`, "both files are made, each as its block", "`.ignore` is not made when it would hold nothing", "`.rgignore` is never made")

### Requirement: The Ignore Block Leaves the User's Lines Alone

A path the lines outside the block already name, with or without a slash or a `!`, SHALL stay out of the block.

#### Scenario: The User's Lines

- **WHEN** the file holds user lines and names a path the block would add
- **THEN** the block leaves that path out and the user's lines are as they were (`hooks/setup/ignore-block.test.ts`, "a path the user already names is left out, with or without a slash"; `hooks/setup/ignores.test.ts`, "the lines outside the block are the lines it had")

### Requirement: The Ignore Block Is Stable on Rerun and Odd Files

A CRLF file SHALL be read and written in CRLF, an unclosed block SHALL be left alone, and a rerun on a settled repo SHALL change no byte.

#### Scenario: A Rerun

- **WHEN** setup runs again on the file it wrote
- **THEN** nothing changes (`ignore-block.test.ts`, "a rerun with the same lines is byte for byte the same")

#### Scenario: An Unclosed Block

- **WHEN** a file has the start marker and no end marker
- **THEN** it is left as it is (`ignore-block.test.ts`, "a block with no closing marker is left as it is")

### Requirement: The Ignore Dialog Shows a Diff and the Grep Effect

The dialog SHALL show the change as a diff and say that the block narrows `Grep` with no `glob` and not `Glob`.

#### Scenario: The Dialog

- **WHEN** setup offers the ignore block
- **THEN** the dialog shows a diff and says the block narrows `Grep` with no `glob`, not `Glob`

### Requirement: Setup Installs Missing Tools

Setup SHALL check `ast-grep` (optional), `betterleaks` (required), and `mo` of Mole (required) on `PATH`. For a missing tool with `brew` on `PATH` it SHALL show the install command (`brew install ast-grep`, `brew install mole`, and the scanner's own command) and run it only on a Yes, and report the exit code and stderr when it fails. With no `brew` it SHALL run nothing and name the releases page.

#### Scenario: A Yes to the Install

- **WHEN** `ast-grep` is missing, `brew` is present, and the user answers Yes
- **THEN** setup shows `brew install ast-grep`, runs it, and reports it (`hooks/setup.test.ts`, "a Yes shows the brew command and then runs it")

#### Scenario: No Package Manager

- **WHEN** `brew` is not on `PATH`
- **THEN** nothing runs and the releases page is named ("a platform with no package manager gets the releases page, and nothing runs")

### Requirement: A No to a Tool Install Is Recorded by Kind

A No for an optional tool SHALL be recorded in the store so the launch notice stays quiet; a No for a required tool SHALL record nothing and SHALL name the command to run.

#### Scenario: A No

- **WHEN** the user answers No for `ast-grep`, and then for `betterleaks`
- **THEN** the first is recorded and the second is not, and the second names the install step ("a No runs nothing and records the decline", "a No to betterleaks records nothing and names the install step")

### Requirement: Setup Points Mole at the Project

When `mo` is on `PATH`, setup SHALL add the git root of the project (else the working folder) to `~/.config/mole/purge_paths`, keeping every line the file held, unless a listed folder, read with `~` expanded, already holds it, because `mo purge` scans only the listed folders once the file names any.

#### Scenario: Purge Paths

- **WHEN** `mo` is on `PATH` and `purge_paths` does not hold the project
- **THEN** the project root is appended once, and a root written as `~/...` already there adds nothing ("setup adds the project root to Mole's purge_paths once, keeping what the file held", "a purge_paths entry holding the project, written with ~, adds nothing")

### Requirement: Start Notices Log Only

At a `startup` session, claudetto SHALL log, with `$.ui.log` and never to the model: a line naming `claude update` when the running base version is below `minimumVersion`, compared by numeric parts; one line for each missing tool, naming its install command or releases page and `/claudetto:setup`; and a disk line when the volume of the project is over 80% full, with its free GiB and the previews `! mo clean --dry-run` and `! mo purge --dry-run`. A resume SHALL log none of these.

#### Scenario: Disk Space

- **WHEN** the volume is 81% full
- **THEN** a disk line logs; at 80% none logs ("a disk over 80% full logs its free space and both Mole previews", "a disk at 80% full logs no disk line")

### Requirement: Tool Notices Repeat by Kind

A required tool's notice SHALL show at every start until it is installed. An optional tool's notice SHALL show once, then stay quiet.

#### Scenario: A Missing Optional Tool

- **WHEN** `ast-grep` is missing at two starts
- **THEN** the first logs one notice and the second none (`hooks/setup.test.ts`, "a startup without ast-grep logs one notice, and the second logs none")

#### Scenario: A Missing Required Tool

- **WHEN** `betterleaks` or `mo` is missing at two starts
- **THEN** both starts log the notice and nothing is recorded ("a startup without betterleaks logs its notice every time, and records nothing", "a startup without Mole logs its install notice every time, and a No to it names the install step")

### Requirement: The Context7 Key Goes Only into `env`

Setup SHALL offer to write a Context7 API key for `bunx ctx7` to `env.CONTEXT7_API_KEY` of the user settings file, typed as the user's own answer. It SHALL skip the offer when the file already holds that key, SHALL write nothing for an empty answer, `Skip`, or `I have no key`, and the report SHALL NOT repeat the key.

#### Scenario: A Typed Key

- **WHEN** the user types a key
- **THEN** it is in `env.CONTEXT7_API_KEY` and the report does not hold it (`hooks/setup.test.ts`, "a typed Context7 key is written to settings env and the report does not repeat it")

#### Scenario: A Key Already Held

- **WHEN** the file already has the key
- **THEN** it is not asked for and not replaced ("a Context7 key already in settings env is the user's: not asked, not replaced")

### Requirement: The Shipped Code Rules Are Offered as Copies

Setup SHALL offer each of the five shipped rules (`useLeastCode`, `noUnrequestedEdits`, `noImpossibleStateGuards`, `useEdgeCaseReport`, `noNarratingComments`) as a copy to `<config>/rules/claudetto/<name>.md`, showing the rule text. It SHALL offer none that the user already holds byte for byte, SHALL store the SHA-256 of a copy it wrote, and SHALL stop the rest when a question is dismissed.

#### Scenario: Each Missing Rule

- **WHEN** the user holds none of the rules
- **THEN** each is a dialog of its own, and a Write puts the shipped text under `rules/claudetto` and writes no settings key (`hooks/setup.test.ts`, "each rule the user lacks is a dialog of its own", "Write puts the shipped text under rules/claudetto and writes no settings key")

#### Scenario: A Dismissed Question

- **WHEN** a rule question is dismissed
- **THEN** the rest are not asked and the report says so ("a dismissed rule dialog stops the rest and says so")

### Requirement: A Changed Shipped Rule Is Logged at Startup

At a `startup` session setup SHALL log once per pair of hashes that an installed rule is `updated` (the installed hash is the stored one) or `modified` (it is not), with both hashes cut to 8 characters, and SHALL log nothing for an identical copy or a rule never installed.

#### Scenario: A Shipped Rule Changed

- **WHEN** the shipped rule differs and the installed copy matches the stored hash
- **THEN** startup logs `updated` once; an edited copy logs `modified` ("a shipped rule changed after setup wrote it is logged as updated, once", "an edited copy is logged as modified even when the shipped file has the newer date")

### Requirement: A Settings Group Keeps the User's Permission Rules

A permission list that a settings group writes SHALL keep every rule the user holds and add ours.

#### Scenario: Git Allow Rules Join the User's

- **WHEN** the user's `permissions.allow` holds `Bash(ls)`
- **THEN** the written list holds `Bash(ls)` and the four git rules (`hooks/setup.test.ts`, "setup on an empty file writes the telemetry env and the eight denies and no Agent deny")

### Requirement: The Smaller Prompt Group Carries Fixed Values

The "Smaller prompt" group SHALL write `disableBundledSkills` `true` and `outputStyle` `claudetto:Concise`.

#### Scenario: The Group Written

- **WHEN** setup writes "Smaller prompt" on an empty file
- **THEN** the file holds these values

### Requirement: The Smaller Prompt Group Turns Off Built-in Plugins

The "Smaller prompt" group SHALL write `enabledPlugins` `false` for each of `cc-plugin-<name>@builtin` for `agents-md`, `plugin-authoring`, `mods-guide`, `tips`, `mermaid`, `responsive-mode`, `diff`, `you-should-know`, `easel`, `claude-platform`, `claude-test`.

#### Scenario: Plugins Written

- **WHEN** setup writes "Smaller prompt"
- **THEN** each of the eleven plugins is `false`

### Requirement: The Smaller Prompt Group Denies Rarely Used Tools

The "Smaller prompt" group SHALL write `permissions.deny` of `Workflow`, `ScheduleWakeup`, `ReportFindings`, `CronCreate`, `CronDelete`, `CronList`, `EnterPlanMode`, `ExitPlanMode`.

#### Scenario: Denies Written

- **WHEN** setup writes "Smaller prompt"
- **THEN** the eight tools are in `permissions.deny`

### Requirement: The Smaller Prompt Group Allows Read-Only Git

The "Smaller prompt" group SHALL write `permissions.allow` of `Bash(git status *)`, `Bash(git diff)`, `Bash(git log)`, `Bash(git show)`.

#### Scenario: Allows Written

- **WHEN** setup writes "Smaller prompt"
- **THEN** the four git rules are in `permissions.allow`

### Requirement: The Auto Mode Group Carries Fixed Values

The "Auto mode" group SHALL write `autoMode` with `allow`, `soft_deny`, `hard_deny`, and `environment` lists replaced, with no `$defaults`, by `AUTO_MODE` (`setup/auto-mode.ts`): one hard rule (Data Exfiltration), nine soft rules, each with its consent-bar `must name` slot, seven allow rules, and two trust entries.

#### Scenario: The Group Written

- **WHEN** setup writes "Auto mode"
- **THEN** the four lists equal `AUTO_MODE` and hold no `$defaults`

### Requirement: The Models and Windows Group Carries Fixed Values

The "Models and windows" group SHALL write `model` Opus 5.5 at `effortLevel` `medium`, `fallbackModel` Sonnet 5.5, `modelSettings` with a `maxEffortLevel` per model, and for Haiku 5.5 an `autoCompactWindow` of 200000; `autoCompactWindow` 300000, `idleCompaction` `false`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` `50.0000`, and the default-model env vars.

#### Scenario: Haiku Window

- **WHEN** the "Models and windows" group is written
- **THEN** `modelSettings["claude-haiku-5-5"].autoCompactWindow` is 200000, below the 300000 of the other models (`settings.ts:96`)

### Requirement: The Worktrees Group Carries Fixed Values

The "Worktrees" group SHALL write `worktree.baseRef` `head`.

#### Scenario: The Group Written

- **WHEN** setup writes "Worktrees"
- **THEN** `worktree.baseRef` is `head`

### Requirement: The Sandbox Group Carries Fixed Values

The "Sandbox" group SHALL write the deny-list block of the `sandbox` spec, with its lists as that spec names them, and no per-tool entry ("the sandbox group lists what is dangerous: home-wide writes, denies for files that run later and for secret stores, any host and service").

#### Scenario: A Cache Variable

- **WHEN** `BUN_INSTALL_CACHE_DIR` is set to a folder under `/Volumes/`
- **THEN** the sandbox's `allowWrite` gains no entry for it, because `/Volumes/` covers it ("A Cache Folder Named by an Env Var: setup writes no entry for it, because allowWrite covers it")

### Requirement: The Subagent Cap Group Carries Fixed Values

The "Subagent cap" group SHALL write `env.CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` 3 for the `claude_pro` plan and 4 for `default_claude_max_5x`, read from the login record, and no group for another plan or for an API key.

#### Scenario: Another Plan

- **WHEN** the login record holds another plan, or the session uses an API key
- **THEN** no cap is written

### Requirement: Setup Caps Subagent Nesting at One

The setup env group SHALL write `env.CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` as `"1"`, and its description SHALL name subagents that start subagents among what it turns off. Claude Code reads that variable and drops the `Agent` tool from a subagent at that depth, so no `tool.call` hook denies a nested agent.

#### Scenario: A Clean Write

- **WHEN** setup writes the env group
- **THEN** `env.CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` is `"1"` (`hooks/setup/settings.test.ts`)

### Requirement: The Protected Paths Group Denies Each Wall's Reads

The "Protected paths" group SHALL write `permissions.deny` `Read(<wall>/**)` for each `protectedPaths` entry, in the form the startup wall notice accepts: `~/` for a path under `~`, `$HOME`, or `${HOME}`, and `//` for any other. With no entry it SHALL be no group.

#### Scenario: Three Spellings

- **WHEN** `protectedPaths` holds `~/.claudetto-holdout`, `$HOME/b`, and `/srv/holdout/`
- **THEN** the deny list holds `Read(~/.claudetto-holdout/**)`, `Read(~/b/**)`, and `Read(//srv/holdout/**)`, and the startup notice finds no wall unguarded (`hooks/setup.test.ts`, "each protected path gets a Read deny that silences the startup wall notice", "the default protected path gets its Read deny", "with no protected path, setup writes no Read deny")

### Requirement: Haiku Explains Each Setup Question and Recommends an Answer

Setup SHALL keep one question per step and SHALL send each question, redacted by betterleaks, with its options to Haiku. When Haiku names one of the options and a reason, the question SHALL end with a "Recommended:" line holding both, and that option SHALL be listed first, with every label unchanged.

#### Scenario: Haiku Recommends

- **WHEN** Haiku answers `{"pick":"Skip","why":"..."}` to a write-or-skip question
- **THEN** the question ends with `Recommended: Skip.` and the reason, and `Skip` is the first option (`hooks/setup.test.ts`, "each setup question ends with Haiku's recommendation, and that option comes first")

#### Scenario: No Usable Answer

- **WHEN** Haiku names a label that is not an option or `""`, does not answer, or the secret scan fails
- **THEN** the question and its options are as they were ("a recommendation that names no option leaves the question as it was")

#### Scenario: A Secret in the Question

- **WHEN** a question shows a value betterleaks flags
- **THEN** Haiku's prompt holds `[REDACTED]` in its place ("Haiku never sees a secret that a setup question shows")

### Requirement: `/statusline` Is Described as Making No Model Call

The `command.describe` hook SHALL give `/statusline` the description "Write claudetto's status line, with no model call".

#### Scenario: The Description

- **WHEN** the engine describes `/statusline`
- **THEN** the description is that text (`hooks/setup.test.ts`, "/statusline is described as making no model call")
