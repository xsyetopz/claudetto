# Mod Loader Constraints

- [x] **CON-007** claudetto shall write mod code under these loader limits: literal `on('<event>', ...)` with direct `$.<ns>.<method>()` calls (no loop, proxy, wrapper, or destructuring of `$`); one unmatched hook per event per module (an event two features hook unmatched belongs to `register.ts`; `on("session.start") is registered twice without a matcher` fails the module); the loader follows `$` by name into a top-level function declaration or a const bound to one, or into an import; it refuses a name bound to a function expression outside the hook's own file (corrected on 2.1.327, chunk-dafpvz32.js@60537: arrows are not refused as such), so a module passes `$` only to a top-level function declaration; `register.ts` chains `onSettingsRead` with `denyBuiltinFetch` (one unmatched `settings.read` per module); hooks import code files only (their own files and `"claude-code"`; not`node:fs`,`node:path`, a package, or JSON); every model-read text in one`texts`file; strict TypeScript flags kept (`strict`,`noUncheckedIndexedAccess`,`exactOptionalPropertyTypes`);`$.tool.register` is unavailable in `classic.SessionStart` ("no session is bound"), so register in the single `session.start` hook; a `command.run` hook answering `goal` without `next()` replaces built-in `/goal`.
