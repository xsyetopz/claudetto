# Decider Transport

- [ ] **RT-018** The Decider shall settle in this order: with no key, a failed scan, or redacted state over 120,000 chars, call `claude-haiku-5-5` at `high` directly; otherwise send one request bundling every question to model `jev-1.14.0` with a 5,000 ms race and one try, except the 429 or 529 backoff below. A 401 or 403 sends Haiku and turns Jev off for the session (the log names the env var, never the key); a 429 or 529 retries `jev-1.14.0` with backoff inside the call site's wall-clock deadline, then sends Haiku (user decision, AskUserQuestion 2026-11-17); a 5xx, throw (closed port, another plugin's URL denial), or timeout sends Haiku for this request; a 400, 413, 415, or 422 sends Haiku and logs an error (status plus up to 200 chars of body); an unknown status logs and retries on the next call. The Haiku call uses the full ID and JSON by question name; a `yes` or option needs evidence copied verbatim from state, else `unsettled`; `isAnswered:false` or unparsable output makes every answer `unsettled`, logs the reason, and never resends. The fallback model is `deciderModel` (default haiku-5-5) at `deciderEffortLevel` (default high). A failed call never reads as an answer. Measured: a real key answered 200 in 257 ms at $0.0033; a bogus key got 401 in 140 ms, then Haiku in 1,400 ms at $0.0019; TTY Jev 170-239 ms against Haiku 1.9-3.7 s. `$.env.get` sees a key in settings `env` (measured, `seen-1`), so `TYPESAFE_API_KEY` lives in user settings env; a project `.env` is not read.
