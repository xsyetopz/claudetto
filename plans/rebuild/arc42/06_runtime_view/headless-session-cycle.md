# Headless Session Cycle

- [x] **RT-020** Superseded by RT-025 and [ADR-0184](../../adr/0184-headless-renewal-by-driver.md). The 2.1.325 design had the mod clear a headless session itself (`$.command.run({command:'clear'})`, then `$.prompt.submit` of the handoff) on a context-size or idle-gap trigger. On 2.1.327 the plugin clear under `-p` is dropped whenever a next prompt is queued (`clearCommandQueue`, chunk-m14bt1pz.js@740648) and fails with "host has ended its input" when stdin has closed; it resolves only with no queued prompt. Headless renewal therefore belongs to the driver, which sends `/clear` as a prompt, and the trigger is a task boundary (RT-027), never an idle gap.
  Basis: measured on claude 2.1.327 (probe A: plugin clear discarded in 3 of 3 runs with a queued prompt, resolved in a rerun with one prompt; probe F: host input ended). Status: superseded.
  Source: handover probes A and F, claude 2.1.327, 2026-11-18, cc-inspect `code cli` with a repo plugin dir, stream-json prompts (reports/2026-11-18-research/handover-probes/probe-a/probe.log, probe-f/probe.log); session-cycle probe, claude 2.1.325, 2026-11-16 (recorded in plans/rebuild-curation.md at commit dc499712).

- [ ] **RT-022** After a driver-sent `/clear`, the first user message of the new conversation holds, in order: the `prompt.context` handover block (`<system-reminder>\n# handover\n…`), the attribution reminder, the `/clear` caveat and command record, then the user's prompt. The handover text does not repeat the `/clear` record and does not refer to it as an earlier step, because the model reads the handover first.
