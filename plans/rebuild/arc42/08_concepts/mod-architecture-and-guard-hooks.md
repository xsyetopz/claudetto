# Mod Architecture And Guard Hooks

- [ ] **CC-060** claudetto shall use one registration file per plugin calling groups in nesting order, no pass-through module (only re-exports; no interface that only forwards to `$`), one definition per shared helper (`isRecord`, `ANY_TOOL`, the writer-tool list Edit/NotebookEdit/Write, `signature`) but a helper two plugins need is defined once per plugin (hooks cannot import outside their plugin folder), descriptive names for two different things under one name (`USER_COMMAND`, `watchDenials`: same name with different meaning misleads more than two copies), and no hyphenated file families. Three or more source files with a shared prefix become a folder or merge (`spec*`, `validate*` to `spec/`, `validate/`; one `ignore.ts` in `useSetup`; `texts/` at three); `register.ts`, `bunfig.toml`, `project.just` follow. Plugin folders hold no Bun-run test file (`tests/<plugin>/`; lab `*.test.ts` and mocks stay; no `tools/` file imports `tests/`; `claudetto-openspec` stays under 110,000 bytes). Keep at most one `tool.check` and one `tool.call` hook per plugin, each with one `.catch` (a guard hook without one fails open); guards are named functions that test the tool's name and pass everything else to `next`, run via `chain`, in the kept guard order; `claude plugin validate --strict --json` lists them with `hasCatch` true and each module's env reads. Fault policy: a fault in `tool.check` leaves the verdict beneath in place (decision D323, which supersedes D321's ask with the failure message); in `tool.call` it refuses; a throw after `next` answered withholds the result with failure text; an overrun makes the catch answer with kind `timeout`; the side-check observer logs and lets the call go; a catch never turns a fault into a normal-looking value; a failed side read does not report success; you-should-know merges two `tool.call` hooks into one whose `.catch` logs via `$.ui.log` and returns `next(e)`.
  Acceptance: `just clones` reports 0 new; plugin folders hold no Bun-run test file; every `$.model.complete` call names a model (one of three full 5.5 IDs), an effort, and a measured `maxTokens` (largest output plus a quarter), and `tools/model-calls.test.ts` fails on aliases, spreads, and computed models.
