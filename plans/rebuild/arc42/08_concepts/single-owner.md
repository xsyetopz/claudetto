# Single Owner

## One Owner Per Responsibility

- [ ] **CC-017** claudetto shall give each responsibility, feature, and failure exactly one owner, with the deciding evidence, in this order: native setting or built-in, mod hook, settings hook, skill, removal; a responsibility with 2-3 owners is merged. The feature map names check, Claude Code version, and result; a feature whose check has not run stays "proposed" and ships no change. When a probe shows a native setting equals a hook, remove the hook and have setup write the setting. Two code paths never write the same file, settings key, or state key (for example `/claudetto:setup` and bare `/statusline` both write `statusLine` through the one `STATUS_LINE` group). Records have one owner too: the tracker owns task state and done criteria; the memory plugin only searches what was tried; a recalled memory is not proof of current state or of user approval; after turning off a plugin's work-list injection, cached lists still showed until cleared and rechecked. Failure mode to runtime check: self-certification to the Stop open-items check; no-progress loops to a stall rule that ends the turn at the first Stop block after a stretch with no file write (`/goal` included); retry after denial to a repeat-denial refusal; destructive actions to a gate, a dangerous list, and the sandbox; critical text buried to long test, build, and lint output cut to head and tail with the whole text saved and built-in descriptions trimmed; sycophancy to the claim check. A prompt change counts as a candidate until a measured A/B over paraphrased and held-out cases. `tool.check` stands where PreToolUse would (it fires after PreToolUse and before the permission prompt); reply checks stay at `classic.Stop`; stallStop, agree-opener, named files (also SubagentStop), command and ask form, graded reply codes, slice commit, and the background task list stay at Stop; a PR merge has no event (SessionEnd covers local branches). One owner per failure sits at one lifecycle point: a component imports only `kernel/`; guards run in one chain per event and each answers or passes; classic shell hooks are used only where a mod cannot act; one module entry sets the wrap order. Rejected settings: `sandbox.network.allowedDomains` (a fixed list breaks the sandbox spec rule; lists merge across scopes) and `sandbox.failIfUnavailable` (aborts the start without sandbox support). Risks: `settings.read` may refuse some keys from a plugin (move to `/claudetto:setup`); the fork at compaction needs output room (falls through to the built-in). Hand-written sandbox exclusions (`excludedCommands`) match only a one-plain-command call (4 of 513); the user's rule of 2026-11-09 bans them.
  Acceptance: no settings key has two writers in the code. Verification: inspection.
