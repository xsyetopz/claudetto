# `claudetto-spec` Evals

Cases for `claude plugin eval`, under the integrity rules of ADR-0193. Requirements: REQ-SPEC-005 to REQ-SPEC-008.

The cases are built to be failed: each hides one trap behind a confident claim in the request, and a careful engineer can pass each from the prompt, the scaffold and the plugin's rules alone.

## Run

Run from the repository root. The scaffold scripts run as the user and need `--scaffold`; `Bash`, `Write`, `Edit` and `mcp__claudetto-spec__spec_check` need `--allow-tools`, which `just eval claudetto-spec` derives from the cases' `allowed_tools`.

```sh
claude plugin eval plugins/claudetto-spec \
  --scaffold \
  --allow-tools Write Edit Bash mcp__claudetto-spec__spec_check \
  --runs 3 \
  --max-cost-usd 15 \
  --ablation with-without \
  --no-publish
```

Results land in `plugins/claudetto-spec/evals/results/`, which git ignores.

## Integrity Rules (ADR-0193)

- Hardened in place: a case keeps its one name, each reported score names the case commit it ran on (`git log -1 --format=%h -- plugins/claudetto-spec/evals/<case>`), and both arms are rerun after any change to a case.
- Graders read files, tool calls, and git state; an `llm` grader is short and never alone.
- Each regex grader has a good and a bad sample in `tools/__tests__/spec-eval-samples.ts` and `spec-eval-stop-samples.ts`; `tools/__tests__/eval-cases.test.ts` fails when a grader has no sample, rejects its good one, or accepts its bad one, when a case has only `llm` graders, when the suite has no single `canary` case, or when a case name ends in `-vN`. A file grader's samples are the scaffold's own file after a list of edits. `tools/__tests__/eval-case-facts.test.ts` checks the test run each scaffold starts from. Run `bun test tools/__tests__/eval-cases.test.ts tools/__tests__/eval-case-facts.test.ts` before the first eval run.
- A case whose baseline arm also scores 1.0 is reported as "does not separate the arms".
- `tool_used: Skill` graders are plugin-fired indicators under `with-without`; the `trivial-*` ones set `arm: both` and score in both arms.
- `spec-review-hollow-test` uses a natural-language prompt, so both arms get the same request. Its earlier, three-gap form measured the `/claudetto-spec:spec-review` command against the plugin's plain answer (REQ-SKILLS-020): on 2026-11-21 (2.1.330, Opus 5.5) the plain case scored 0.98 with the plugin and 1.00 without over 6 runs per arm ($1.73), and the command scored 0.87 over 3 runs ($0.14). The plain case ran on case commit 1dc0fd52a, and its prompt and graders match; the command case was never committed, so its score names no case commit. The command did not beat the plain request, so it was removed with its slash case. The plain case stays as a no-harm check on review requests.
- The cases as replaced on 2026-11-23 have no score yet; `contradiction-implicit`, `spec-fix-skill` and `spec-fix-command` were removed, and their traps moved into `contradiction` and `spec-edit-skill`.
- Each case keeps its prompt in `case.yaml` under `execution.prompt`, with no `prompt.md`: `prompt.md` rejects unknown frontmatter keys, so it cannot carry the `title` that the repo's markdownlint MD041 rule asks of a Markdown file without a heading, and a heading in the body would change the prompt Claude receives.
- Each case folder holds its own copy of `scaffold.sh` because the docs resolve `scaffold_script` inside the case directory.
