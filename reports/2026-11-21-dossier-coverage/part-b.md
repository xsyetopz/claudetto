### Uncovered

- B10 Honesty failure under pressure: proposed OUT. A plugin cannot elicit a model's separately held belief, so honesty-under-pressure (MASK) is a model-evaluation property outside plugin scope.
- B16 Missing descendant audit events: proposed OUT. Child events are emitted by Claude Code and claudetto ships no audit log (OUT-024 dropped `runs.jsonl`), so a plugin cannot add events Claude Code does not send; confirm with a probe before adopting.
- B18 Non-blocking enforcement mistaken for denial: proposed REQ. claudetto shall ship each gating hook so that it denies through a documented blocking exit or decision and shall state in its reason that the action did not run when the hook cannot block; a vanilla reproduction registers a PreToolUse hook that exits 1 on a Bash call, runs `claude` against a fake Messages API, and checks that the command still executes while the agent reports it as blocked.
- B21 Hardcoding visible tests: proposed OUT. Fitting examples versus the intended contract needs a semantic grader of the implementation, which ADR-0104 excludes (no Stop claim grader), and REQ-GUARDS-058 already walls hidden tests for claudetto's own evals.
- B23 Pre-existing solution substitution: proposed OUT. Telling a found answer from the agent's own work needs a judgment of reply text, which ADR-0104 excludes, and no structured signal in tool arguments separates the two.
- B26 Monitor evasion: proposed OUT. Monitor evasion is an optimisation pressure seen in constructed evaluations (SHADE-Arena) and a plugin hook is itself an oversight layer, so it cannot measure or cure the pressure.
- B27 Evaluation-aware behavior: proposed OUT. Evaluation awareness is a model property seen in test settings; a plugin neither controls training nor can tell a real session from a test.
- B28 Alignment faking: proposed OUT. Alignment faking is a training-context phenomenon in model evaluation; a plugin has no access to training or to the model's internal compliance reasons.
- B29 Sandbagging: proposed OUT. Sandbagging is deliberate underperformance in an evaluation setup; a plugin cannot distinguish it from a capability limit.
- B30 Unfaithful explanations: proposed OUT. Unfaithful reasoning is a property of model reasoning traces; a plugin cannot verify that stated reasoning matches the computation.
- B31 Early-assumption lock-in: proposed OUT. Early-assumption lock-in across turns is a model property; REQ-HANDOVER-018 renews sessions for cost, and no probe shows renewal repairs a wrong early solution.
- B35 Distributed boundary violation: proposed OUT. Splitting proposal, execution and approval across agents is a multi-agent deployment risk; claudetto ships four fixed agents with depth 1 (REQ-DELEGATION-044, REQ-SETUP-027) and no approval agent to split.
- B40 Oversight generalization failure: proposed OUT. Detector generalisation is a property of an oversight model's training and evaluation; claudetto ships no detector.
- M09 Hardcoded test cases: proposed OUT. Detecting an implementation fitted to visible examples needs a semantic grader of code, which ADR-0104 excludes; claudetto walls hidden tests only for its own evals (REQ-GUARDS-058).
- M10 Fake integration: proposed REQ. claudetto-spec shall list each spec scenario whose only citing tests replace the integration with a stub or mock; a vanilla reproduction asks the agent for a feature that crosses a service boundary, then checks whether the passing test mocks that boundary and the reply calls it integrated.
