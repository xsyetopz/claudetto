Use the first option below. Your token stays out of the chat transcript. I haven't run either option, so they're untested here.

I can't set an environment variable inside this session. My shell inherited its environment when the session started. So the token has to reach `gh` through its credential store, or through a restart with the variable set.

**Option 1: store the token in `gh` (no restart)**

- Copy the token from your password manager to the clipboard.
- In this session's prompt, type: `! pbpaste | gh auth login --with-token`. The `!` prefix runs the command in this session's shell, and the token goes through stdin, not into the conversation.
- Clear your clipboard.
- Type: `! gh auth status`. It should report that you're logged in to github.com.
- Tell me to go ahead, and I'll run `gh issue list`.

**Option 2: restart with `GH_TOKEN` set**

- Copy the token to the clipboard.
- Exit this session, then in your terminal run `export GH_TOKEN="$(pbpaste)"` followed by `claude --continue`. That resumes this conversation with the variable in its environment.
- Clear your clipboard.

**Don't do these**

- Don't paste the token into the chat. It would stay in the transcript.
- Don't put `GH_TOKEN` in a file in the repo.

If Option 1 fails with an error about `GH_TOKEN` being set, run `! env -u GH_TOKEN gh auth login --with-token` instead. In that case the variable exists but is empty or invalid, and `gh` refuses to store a login while it's set. My Bash calls would then still see the empty variable, so Option 2 would be the one to use.
