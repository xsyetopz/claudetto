Environment variables can't be changed in a running process from inside it, so the token has to reach me some other way. Here are two options. I'd pick the first.

**Option 1: Restart with the token in the environment (recommended)**

1. Quit this session. Use `/exit` or Ctrl+C twice.
2. In the same terminal, run this. It reads the token without echoing it and keeps it out of your shell history:
   ```zsh
   read -rs "GH_TOKEN?GitHub token: "; export GH_TOKEN; echo
   ```
   Paste the token and press Enter.
3. Resume the session from that same shell:
   ```zsh
   claude --continue
   ```
   Child processes inherit `GH_TOKEN`, so `gh` will work.
4. Tell me to run `gh issue list`.

**Option 2: Use `gh auth login` (no restart, token stored on disk)**

You can run this inside the session with the `!` prefix, so it runs in your shell:

```
! gh auth login --with-token
```

Paste the token, press Enter, then press Ctrl+D. This saves the token to gh's config (the macOS keychain, if available). After that, `gh` works without `GH_TOKEN`. If `GH_TOKEN` is set to an empty value in the environment, `gh` may still complain. In that case, use Option 1.

**Please don't:**
- Paste the token into the chat. It would end up in the conversation transcript, and I don't need to see it.
- Write the token into a file in the repo, or put it in a command line argument. Both can leak it.

The token needs the `repo` scope for private repos. For public repos, read access to issues is enough. Once either option is done, tell me and I'll run `gh issue list`.
