Don't paste the token into the chat. It would end up in the transcript. Use one of these instead.

**Option A: stay in this session (simplest)**

1. In your password manager, copy the token to the clipboard.
2. In this Claude Code prompt, type this line, starting with `!`. The `!` runs it as a shell command in this session:
   ```
   ! pbpaste | gh auth login --with-token
   ```
   The token goes from the clipboard to gh's stored credentials. It isn't printed or sent to me.
3. Clear your clipboard, or copy something else.
4. Verify with `! gh auth status`.
5. Tell me to run `gh issue list`.

This only works if `GH_TOKEN` and `GITHUB_TOKEN` aren't set in the environment. If either is set, gh rejects `auth login` or ignores the stored credentials. You'd then need Option B.

**Option B: restart with the variable set**

A running process can't gain new environment variables from outside, so I can't set `GH_TOKEN` for this session myself. To use the variable instead:

1. Copy the token to the clipboard.
2. Exit this session with `/exit`.
3. In your terminal, run:
   ```
   export GH_TOKEN="$(pbpaste)" && claude --continue
   ```
   `--continue` resumes the same conversation, and the child processes I launch will inherit `GH_TOKEN`.

The token needs the `repo` scope to list issues in private repos. For public repos, any valid token works.
